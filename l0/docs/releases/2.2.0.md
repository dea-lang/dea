# Dea/L0 2.2.0

Dea/L0 2.2.0 delivers independent compiler-stage references and verified offline documentation in compiler
distributions. It also fixes signed negation overflow and parser recovery, improves build diagnostics, and strengthens
development and validation workflows. The minor version recognizes these substantial documentation and delivery
improvements while preserving the existing L0 language, compiler CLI, standard-library, and public C interfaces.

## Independent references and offline documentation

- Stage 1 and Stage 2 now have independent HTML/PDF references, source inventories, search indexes, and successful
  previews. Shared standard-library and runtime contracts appear in both; the public distribution reference is Stage 2.
- Compiler archives include verified offline Stage 2 HTML and a complete PDF under `share/doc/dea/l0/autodocs/stage2/`.
  A documentation manifest checks source and version identity, completeness, and file digests before packaging and after
  copying.
- Release assets include the stage-qualified PDF, a separate offline HTML/PDF bundle, and a separate Chirpy Markdown
  export. `SHA256SUMS` covers the complete asset set.
- Reference generation preserves enum payloads, struct fields, nullable and pointer types, multiline declarations, and
  source positions. Native C implementations and language bindings are extracted independently to avoid mixing contracts
  for unrelated functions with the same name.
- C function contracts are consolidated at definitions, with concise matching header comments. PDF destination and
  cross-reference checks catch unresolved links in final documents; documentation toolchains are pinned in CI.

## Compiler correctness and diagnostics

- Both compiler stages lower integer negation through checked arithmetic. Negating the minimum 32-bit `int` now fails
  deterministically instead of invoking signed-overflow undefined behavior in generated C, including in unchecked
  pointer mode. Operands remain evaluated once, and `byte` negation retains promotion to `int`.
- Parser recovery respects the brace depth of a failed declaration, preventing nested declarations from being mistaken
  for subsequent top-level declarations.
- Temporary-directory diagnostics identify the failed resolution, inspection, ownership, or sticky-bit requirement.
  Stage 2 captures inspection evidence once and includes the failing Windows operation and error where applicable.

## Development and validation

- Cleanup validates build destinations, removes hidden build artifacts, and correctly handles custom build directories.
- AddressSanitizer capability probes require an actual sanitizer report, avoiding false positives from compilers that
  silently accept unsupported sanitizer flags.
- Windows shared tooling uses native CPython. A separately provisioned UCRT64 Python environment runs the complete Stage
  1 compatibility suite without replacing the shared virtual environment.
- Normal and extended validation have explicit tiers. Level suites validate their own inputs; shared repository checks
  run separately, and CI routes predecessor changes to affected consumers without making L0 depend on successor sources.
- Workflow logs expose inputs and documentation build progress, and hosted toolchain baselines are pinned by workflow
  role.

## Tooling migration

- Windows compiler archives now use `dea-l0-lang_windows-x86_64_<timestamp>.zip` instead of `windows-amd64` in the
  filename, and `VERSION` records `arch: x86_64` instead of `arch: AMD64`. Package architecture aliases are normalized
  (`amd64` to `x86_64`, `aarch64` to `arm64`) in both metadata and filenames. The flat metadata format, existing OS
  spelling, and compiler's raw host report are preserved. Update scripts that match historical names or exact
  architecture values; consumers of older releases should continue accepting both spellings. Published historical
  archives and checksums are unchanged.

- Replace `make test-all` with `make test-extended`, including Docker invocations such as
  `make docker CMD=test-extended`. `make test` remains the normal suite; L0 `test-extended` adds the broad Stage 2
  ARC/memory trace sweep.

- Before `make dist`, generate a matching complete Stage 2 documentation bundle and pass its absolute path through
  `DOCS_ARTIFACT`. From `l0/`:

  ```bash
  make docs-artifacts DOC_STAGE=stage2 DEA_DIST_VERSION=2.2.0
  DOCS_ARTIFACT="$PWD/build/docs/artifacts/dea_l0_stage2_autodocs.tar.gz" DEA_DIST_VERSION=2.2.0 make dist
  ```

  Source identity and version must match; stale or partial bundles are rejected. `make install PREFIX=<prefix>` remains
  compiler-only and does not require TeX. Fast preview PDFs cannot serve as distribution artifacts.

- Documentation builds default to both stages. Select `DOC_STAGE=stage1|stage2|all` for Make, or
  `--stage stage1|stage2|all` for `scripts/gen_docs.py`. Outputs and previews move under their respective `stage1/` and
  `stage2/` directories, with PDFs named `dea_l0_stage1_api_reference.pdf` and `dea_l0_stage2_api_reference.pdf`.

- Download and export automation must use the new release asset names: `dea_l0_stage2_api_reference-l0-v2.2.0.pdf`,
  `dea_l0_stage2_autodocs-l0-v2.2.0.tar.gz`, and `dea_l0_stage2_api_reference-l0-v2.2.0.tar.gz`. The last archive is the
  Chirpy export, not the offline HTML/PDF bundle. Historical published assets retain their names. Pages retains its
  unversioned Stage 2 entrypoint and the old PDF URL as a compatibility copy; retired Stage 1 paths show migration
  notices.

- On Windows, recreate any shared `.venv` built with MSYS2 Python using native CPython and root `make venv`. Reserve
  MSYS2 Python for the separate Stage 1 compatibility environment; see [l0/README-WINDOWS.md](../../README-WINDOWS.md).

- The former L0 `test-shuffle-sources` check now belongs to shared repository tooling. Root aggregate validation runs it
  with the other repository checks.

## Compatibility

- No new L0 syntax, compiler CLI options, standard-library APIs, public C signatures, or diagnostic codes are
  introduced. Diagnostic wording and recovery on malformed input improve, and overflowing negation now enforces the
  existing defined-arithmetic contract.
- The standard-library sources and runtime-header code are unchanged from 2.1.1; runtime-header edits improve contracts
  and generated reference documentation.
- The tooling and asset migrations above require updates to affected developer and documentation-consumer scripts. This
  release does not add L1/L2-only numeric types, bitwise operators, or compiler modes.
