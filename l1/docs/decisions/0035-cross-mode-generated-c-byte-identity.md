# ADR-0035: Cross-Mode Generated-C Byte Identity

- Decision date: 2026-08-23
- Last edited: 2026-09-11
- Status: Accepted

## Context

Per-module `--gen` and compile-only already shared one backend operation, while multi-CU build/run staged and optionally
retained the same module outputs. The completed producer set needs one durable identity rule so destination paths,
private workspace names, caller mode, or retention cannot silently change compiler artifacts.

The executable wrapper is generated by link orchestration rather than the module backend. Explicit interface/object
providers have no source body to regenerate. Managed bundled providers use toolchain-owned sources and verified semantic
interfaces; their native profiles need not retain generated-C scratch.

## Decision

For identical source, resolved graph, verified interfaces, fingerprints, byte-affecting code-generation settings, and
compiler version:

- `l1c --gen MODULE -o module.c` is byte-identical to the `.c` published by `l1c --compile MODULE --keep-c`.
- The same module bytes appear at the canonical mirrored path in build and run retained-C trees.
- Build/run retention copies exact command-generated application module bytes submitted to the host compiler without
  regenerating or rewriting them. Managed bundled module C is regenerated through the same canonical backend and
  selected toolchain inputs, independently of missing or modified native-profile C scratch.
- Output destinations, invocation-private workspace identities, and caller mode do not affect generated module bytes.
- Explicit interface/object-backed graph nodes contribute no C file; their canonical `.c` companion is neither required,
  read, nor regenerated.
- `__dea_wrapper.c` remains a separate link-orchestration artifact. It is compiled and retained exactly, but it has no
  `--gen` or compile-only counterpart and is excluded from module-C identity comparisons.

`backend_generate_module(...)` is the only production backend generation entrypoint. The legacy complete-source-closure
generator, combined initialization walk, and backend-owned process wrapper are removed.

## Rationale

- One byte contract makes generated C a stable compiler artifact independent of the producing CLI mode.
- Copying application compiler inputs makes retention auditable. Canonical managed regeneration preserves byte identity
  without requiring native profiles to retain or trust optional generated-C scratch.
- Keeping the wrapper outside module identity preserves the separation between module compilation and link
  orchestration.
- Explicit interface/object providers remain authoritative reusable artifacts without an undeclared source or C
  dependency.

## Consequences

- Tests compare all four producer modes for source-only and mixed source/interface graphs under every supported
  byte-affecting setting.
- Host-compiler recording verifies exact retention of application module and wrapper inputs. Managed-provider tests
  compare regenerated C across producer modes, including warm profiles with missing or poisoned C scratch.
- Future Stage 2 and other L1 backend implementations must preserve this artifact identity contract.
- Native object bytes remain outside the guarantee because the selected host toolchain owns their remaining contents.
