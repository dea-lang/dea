# Dea/L1 0.1.0

Canonical L0-implemented L1 development toolchain. This release does not declare language or toolchain stability.

Dea/L1 0.1.0 introduces the canonical `l1c` toolchain for `.l1` programs, with separate compilation, verified module
interfaces, managed native support, and standalone installation. It includes the L1 standard library and runtime, four
platform distributions, and matching offline HTML and PDF references.

## Language and standard library

- Functions, structs, enums, type aliases, module exports, alias imports, and selective imports support modular
  programs. Control flow includes `if`, `while`, `for`, `match`, `case`, and `with` / `cleanup`.
- Fixed-width signed and unsigned integers, bitwise operations, `float`, and `double` are supported, including wide
  integer literals and checked scalar constant expressions.
- Fixed-size arrays `T[N]` and non-owning slices `T[]` provide checked indexing, contextual array literals, fill
  constructors, and `len` / `slice` operations.
- Function pointers support indirect calls, nullability, and explicit unsafe signatures. L1-defined variadic functions
  use trailing `T...` parameters and support final `pack...` forwarding.
- Explicit nullability, ARC-managed strings, and `new` / `drop` provide the current value and ownership model.
- The standard library covers I/O, strings and text, paths and filesystems, time, randomness, assertions, optionals,
  containers, integer helpers, and real-number operations. Wide integer conversion and I/O helpers accompany the
  extended integer types; filesystem sizes and modification seconds use `long?`.

## Separate compilation and linking

- `-c` / `--compile` produces a native object and its sibling `.l1m` interface without invoking the final linker.
  `--keep-c` retains generated C for inspection.
- Verified `.l1m` interfaces describe exported declarations and dependencies. Public-surface fingerprints detect
  inconsistent interfaces before semantic replay or linking.
- Ordered `-I` / `--interface-path` roots select imported interfaces. Build, run, and C generation can fall back to
  source when no interface is selected; compile-only requires interfaces for non-virtual imports.
- `-k` / `--link` links separately compiled Dea objects using their sibling interfaces, validates dependencies and the
  selected entry module, and constructs deterministic module initialization and reverse finalization order.
- External libraries, foreign objects, library search paths, runtime search paths, and raw linker arguments are
  supported through the documented linking options. Standalone linking does not compile sources or infer external
  library dependencies.

## Runtime safety and native preparation

- Checked runtime builds validate pointer access and allocation provenance. Raw allocations, `new` allocations,
  ARC-managed storage, and externally owned storage retain distinct lifetime and release contracts.
- `--check-basic` provides reduced pointer validation; `--unchecked` disables the checked-pointer machinery. ARC and
  memory tracing support diagnosis under the documented checking-mode constraints.
- Native standard-library and runtime support is prepared in a separate writable cache. Installed toolchains can reuse
  compatible prepared support without modifying the installation or depending on a source checkout.

## Installation and release assets

- Native archives cover Linux x86_64, macOS Intel, macOS ARM, and Windows x86_64 with MSYS2 UCRT64. Each archive
  contains the canonical compiler, matching library/runtime inputs and interfaces, version and inventory metadata, and
  offline documentation.
- Installed compiler use does not require L0, Python, Make, or the source checkout. Producing native programs still
  requires supported host compiler/linker and preparation tools, with a writable support-cache location.
- The release includes four platform archives, a matching offline HTML/PDF bundle, a standalone API-reference PDF, and
  `SHA256SUMS` covering those six payload files. Verify downloaded files against the checksums before use.
- Source builds use an explicitly selected L0 bootstrap compiler. Local `make install` and `make dist` use the same
  canonical toolchain contract as the release archives.

## Compatibility and current limitations

- L1 remains a development language and toolchain. This version does not freeze its feature scope or promise stable
  source, module-interface, or binary compatibility across future releases. L0 remains the stable toolchain.
- Slices are escape-restricted non-owning views. Owning dynamic buffers, shared buffers, general escape-capable slices,
  address-of expressions, and generics are not part of the current language surface.
- Full managed native preparation requires a supported GCC toolchain, upstream Clang 16 or newer, or Apple Clang with
  the required configuration capabilities. Upstream Clang 14/15 are not supported for the full preparation workflow.
  Windows native compilation uses the UCRT64 environment.
- Native objects and executables remain specific to their host toolchain and platform. Verified Dea interfaces do not
  replace host linker checks for native format, architecture, or symbol compatibility.
