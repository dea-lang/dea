## Summary

The [generated-C foundation plan][generated-c-foundation] first migrates `--gen` and compile-only to one shared
per-module generation operation and stabilizes compile-only compiler-visible paths. The [build/run plan][build-run] then
uses that operation for every source-backed compilation unit and retains the complete generated-C tree.

This completion plan begins after both predecessors land. It proves byte identity across `--gen`, `-c --keep-c`,
`--build --keep-c`, and `--run --keep-c`, then removes `backend_generate(...)` and the legacy combined initialization
and process-wrapper paths. Keeping this plan separate prevents build/run from depending on a plan whose final phase is
itself blocked by build/run.

## Dependencies and Ownership

1. The completed [generated-C foundation plan][generated-c-foundation] owns per-module `--gen`, the shared generation
   operation, `--gen` versus compile-only byte identity, stable compile-only staging, and supported-toolchain object
   determinism.
2. The [build/run plan][build-run] must land before this plan begins. It owns multi-CU orchestration and the retained
   module/wrapper C tree whose bytes this plan verifies.
3. The closed [lifecycle plan][lifecycle] owns target-only module emission and the transitional retention of the legacy
   whole-program generator until all callers migrate.
4. The closed [compile-only plan][compile-only] owns publication and rollback; this plan does not change those
   semantics.
5. This plan owns the complete four-mode identity proof, removal of the legacy generator and superseded tests, final
   generated-C documentation, and its ADR lifecycle.

## Final Generated-C Identity Contract

For identical source, resolved graph, verified interfaces, fingerprints, code-generation settings, and compiler version:

1. `l1c --gen MODULE -o module.c` is byte-identical to the `.c` published by `l1c -c MODULE --keep-c`.
2. The same byte sequence appears at the module's canonical mirrored path in build/run retained-C trees.
3. Retention copies the exact bytes passed to the host compiler; it never regenerates or rewrites module C.
4. Output destinations, invocation-private workspace names, and caller mode do not affect generated bytes.
5. The wrapper remains a separate link-orchestration artifact named `__dea_wrapper.c`; it has no `--gen` or compile-only
   counterpart.
6. No production caller or test retains the legacy complete-source-closure generator.

## Implementation Phases

### Phase 1: Verify four-mode identity

Add cross-mode fixtures that compare `--gen`, compile-only retention, build retention, and run retention for source-only
and mixed source/interface graphs under identical code-generation settings. Verify that retained bytes are the exact
compiler inputs and that provider C is neither required nor regenerated for interface/object-backed nodes.

### Phase 2: Retire whole-closure generation

Remove `backend_generate(...)`, combined whole-closure definition walks, the backend-owned process wrapper and
whole-program initialization chain, and tests whose only purpose was preserving superseded single-CU output. Keep the
standalone link wrapper and per-module backend unchanged.

### Phase 3: Documentation and lifecycle

Finalize shared CLI and L1 backend, architecture, separate-compilation, project-status, roadmap, and initiative
documentation. Add the generated-C identity ADR, amend ADR-0020's transitional legacy-generator statements, and close
this plan after proving no legacy production caller remains.

## Diagnostics

No new diagnostic is expected. This plan removes a legacy implementation path and verifies artifact identity without
adding a CLI surface. Re-check the live catalog if implementation exposes a genuinely distinct failure; otherwise reuse
the owning generated-output, retained-tree, graph, compile, and link diagnostics.

## ADR Impact

- Decision: Preserve byte-identical per-module C across `--gen`, `-c --keep-c`, and retained build/run output.
  - Scope: L1
  - Disposition: New ADR
  - ADR: `l1/docs/decisions/0035-cross-mode-generated-c-byte-identity.md`
  - Rationale: Four-mode identity is a durable compiler-artifact contract that becomes fully testable only after
    build/run fan-out lands.
- Decision: Retire the transitional legacy whole-closure generator after all production callers migrate.
  - Scope: L1
  - Disposition: Amend ADR
  - ADR: `l1/docs/decisions/0020-per-module-backend-and-lifecycle-abi.md`
  - Rationale: ADR-0020 deliberately retained the legacy generator only during the staged multi-CU migration.

## Non-Goals

1. Migrating `--gen`, changing its CLI, or stabilizing compile-only staging; the prerequisite foundation plan owns those
   changes.
2. Implementing or changing build/run graph fan-out or retained-tree policy.
3. Changing compile-only publication, rollback, object determinism, or concurrency guarantees.
4. Adding complete-tree generation, build caching, incremental invalidation, or package resolution.
5. Changing L0 generated-C behavior.

## Completion Notes

- Added a six-setting source-only and mixed source/interface matrix that compares module C across `--gen`, compile-only,
  build, and run, and captures the host compiler's exact C inputs for byte comparison.
- Verified that an authoritative `.o + .l1m` provider is consumed without reading or regenerating provider C, while the
  separately named retained wrapper exactly matches its host-compiler input and remains outside module identity.
- Removed the legacy whole-closure backend entrypoint, combined initialization chain, backend-owned process wrapper,
  obsolete output-kind state, and their superseded tests and build-driver helpers.
- Refreshed the CLI contract and live L1 architecture/backend/separate-compilation/status/roadmap/initiative docs, added
  ADR-0035, and amended ADR-0020 plus the intervening generated-C/build-run ADRs.
- Validation passed on 2026-08-23: the 12-test focused regression set, `make -C l1 clean test-all` with 67 normal and 44
  broad trace tests, environment stackability, and all four shipped examples.
- Independent read-only review found and prompted removal of the remaining legacy-only helpers and corrected the
  source-only identity case to use a genuinely source-backed single-module graph; the full validation tier was rerun
  after both fixes.

## Verification Criteria

01. One fixture proves identical module C across `--gen`, `-c --keep-c`, `--build --keep-c`, and `--run --keep-c`.
02. Identity holds for source-only and mixed source/interface graphs under each supported code-generation setting.
03. Build/run consumes an `.o + .l1m` provider whose canonical `.c` is absent without regenerating or reading it.
04. Retained module C is the exact byte sequence passed to the host compiler.
05. The retained wrapper remains separately named and is excluded from module-C identity comparisons.
06. No production caller or test references `backend_generate(...)`.
07. Superseded whole-closure, combined-initialization, and backend process-wrapper code and tests are removed.
08. Existing build, run, compile, gen, and link behavior remains covered by normal and trace tests.
09. Focused tests pass, followed by `make -C l1 clean test-all` before closure.
10. Help and stable documentation describe only the final per-module generated-C and retained-tree contracts.
